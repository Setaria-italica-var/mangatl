# 低质量 OCR 的模型辅助校验

## 问题

装饰性字体、密集小字、艺术标题上，manga-ocr 会输出「看起来像字但不是字」的结果：

```
原文（人眼）：顔も判らないのに選べない…ですか？
manga-ocr ：風迷Ｒミｍ中～★織村とし
```

把它翻译出来必然是乱码，擦掉原字再嵌上乱码比不处理更糟。这类失败**不是阈值问题**，
单靠调合并规则或置信度解决不了，需要第二意见。

## 设计原则

1. **只在可疑处花钱**：正常对白占大多数，不能每块都跑重模型。
2. **绝不臆造**：所有校验只做「接受 / 拒绝 / 二选一」，不生成新文本。
3. **拒绝有兜底**：判不准就标 `needs_review` 并保留原文，删掉译文，不留空气泡。
4. **可解释**：每条决策记录来源与分数，便于回查。

## 分层方案

```
                     ┌──────────────────────────────┐
   每个文字块 ──────▶ │ L1 语言合理性（无模型，<1ms） │
                     └──────────┬───────────────────┘
                        score ≥ 0.7?  ── 是 ──▶ 接受
                                │ 否
                     ┌──────────▼───────────────────┐
                     │ L2 第二引擎 RapidOCR(japan)   │  ~80ms/块
                     └──────────┬───────────────────┘
                       两候选融合，score ≥ 0.6? ── 是 ──▶ 接受较优者
                                │ 否
                     ┌──────────▼───────────────────┐
                     │ L3 LLM 文本裁判（可选）        │  ~1s/页
                     └──────────┬───────────────────┘
                       裁判给出选择/拒绝
                                │ 仍不确定
                     ┌──────────▼───────────────────┐
                     │ L4 视觉模型兜底（可选）        │  ~2–8s/块
                     └──────────┬───────────────────┘
                                │ 失败
                           needs_review + 不擦除
```

### L1 语言合理性（已实现）

`domain/plausibility.py`：按脚本构成打分，纯统计、无模型。

- 假名/汉字占比越高分越高
- 全角+半角拉丁混用 → ×0.2（OCR 噪声的典型特征）
- 全角拉丁占比 > 20% → ×0.5
- 同一字符连续 ≥3 次 → ×0.6
- 单字符 → ×0.5
- 标点/装饰（♥★♪）不计入，不惩罚

实测：正常对白 0.85，`ｒＪＳｍｅｔｔｅｒｄＰｌｌｙｐ` 0.04，
`ＭＳＣＲＭＡＮＡＰ聖Ｖに懸册一` 0.19。当前阈值：**≥0.45 才允许擦除**。

### L2 第二引擎（已实现）

`adapters/ocr/hybrid.py` + `rapid.py`（`Rec.lang_type="japan"`）：

- 仅在 L1 判为弱（空/1 字/乱码）的块上调用
- 两个候选按 plausibility 择优，而不是「取更长」
- 两个都 <0.5 → `needs_review=True`，流水线拒绝擦除

### L3 LLM 文本裁判（待实现）

复用现有 OpenAI 兼容端点，但**只发文本、不发图**，成本极低：

```json
请求：{"page_context": ["上一块原文","下一块原文"], "candidates": [{"source":"manga_ocr","text":"…"},{"source":"rapid","text":"…"}]}
响应：{"pick": 0, "confidence": 0.8, "reason": "第一候选是乱码"}
```

- 触发条件：L2 后 0.45 ≤ score < 0.7，或两候选相近（编辑距离 < 0.3）
- 预算：每页最多 N 块（默认 8），超预算直接 `needs_review`
- 价值：能识破「形态合法但语义不通」的噪声，L1 做不到

### L4 视觉模型兜底（可选插件）

只对最终 `needs_review` 的块跑，输出文本 + 置信度。

| 候选 | 体积/显存 | 许可 | 备注 |
|---|---|---|---|
| **Qwen2.5-VL-3B-Instruct** | int4 约 3 GB，8 GB 显存可跑 | Apache-2.0 | 中文/日文漫画可读，推荐 |
| InternVL2.5-2B | int4 约 2 GB | MIT | 更小，日文弱一些 |
| GOT-OCR2.0 | 580M | Apache-2.0 | 端到端 OCR，日文覆盖有限 |
| Surya 2 | 需 vLLM/llama.cpp | 权重 OpenRAIL-M | 部署重、商用受限，**不推荐** |

约束：`--vision-model` 显式开启才加载；显存不足自动降级为仅 L1–L3；
输出必须再过一次 L1 校验，低于 0.5 一律丢弃。

## 决策表

**重要**：低分不等于放弃。气泡内的文字必须翻译，低分只代表"原文可能读错了，需要
额外校验"。只有当所有校验都拿不到可用原文时，才退回保留原文。

| plausibility | 行为 |
|---|---|
| ≥ 0.70 | 直接采用，正常擦除 + 翻译 |
| 0.45 – 0.70 | **触发校验**：L2 第二引擎 → L3 LLM 裁判；采用校验结果后照常擦译 |
| < 0.45 | **强制校验**：L2 + L3，必要时 L4 视觉读图；拿到可信原文后照常擦译 |
| 校验全部失败 | 标记 `needs_review`；若仍无原文则保留原图（唯一例外），否则用最佳候选擦译并标注可疑 |

`ocr_score` / `ocr_source` 写入 `project.json`，`mangatl inspect` 可直接按分数筛出可疑块。

## 数据与可观测性

`TextBlock` 增加两个字段（持久化）：

- `ocr_score: float` — 最终采用候选的 plausibility
- `ocr_source: str` — `manga_ocr` / `rapidocr` / `llm` / `vision`

`mangatl inspect` 增列 `score`、`source`，便于按分数筛选可疑块。

## 实测（10 页样本，L1–L3）

| 指标 | 数值 |
|---|---|
| 文字块 | 89 |
| 高可信 ≥0.70 | 47 |
| 中 0.45–0.70 | 23 |
| 低 <0.45 | 16 |
| L3 修复成功 | **2**（其余模型返回空） |
| 需人工复核 | 32 |

结论：**纯文本修复对装饰字体基本无效**，必须看图。L4 的接入见
`docs/local-vision-setup.md`（Ollama 一条命令即可）。

## 实施顺序

1. ✅ L1 plausibility + 阈值门控
2. ✅ L2 hybrid 融合（japan 模型）
3. ⬜ L3 LLM 裁判（约 150 行 + 测试，复用现有翻译端点）
4. ⬜ L4 视觉兜底（可选依赖，约 200 行）
5. ⬜ `inspect` 增加分数列 + 按分数导出待修块

## 验收指标

在一本 180 页的样本上：

- 错误擦除率（背景/画稿被擦）< 1%
- 乱码译文率（人工抽样 50 块）< 3%
- `needs_review` 占比 5–10%（太低说明门控失效，太高说明 OCR 太弱）
- 额外耗时：L1+L2 < 总时长 40%；L3 可忽略；L4 仅 suspicious 块
