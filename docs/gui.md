# 桌面编辑器（MVP）

## 启动

```bat
.venv\Scripts\activate.bat
uv pip install "mangatl[gui]"        # 一次即可，装 PySide6
python -m mangatl gui samples\vol1
```

| 图标 | 模块 | 内容 |
|---|---|---|
| ✎ | 编辑 | 块文本/译文/角色、应用、重识别、翻译、排版、删除；区域重检测/擦除/添加 |

## 预览原图 / 擦除 / 结果

工具栏第 3 组是三个互斥的预览开关：

| 模式 | 快捷键 | 显示 | 叠加层 | 选择方式 |
|---|---|---|---|---|
| 原图 | `Ctrl+1` | `<项目>/<页名>` | 全部检测框（按角色着色） | 点选/框选**文本块**，也可拉套索做区域 |
| 擦除后 | `Ctrl+2` | `inpainted/<页名>` | **红色高亮 = 已被擦掉的像素** | **只做区域选区**；不显示、不选中文本块 |
| 排版结果 | `Ctrl+3` | `result/<页名>` | **全部文字框**：已翻译=白色虚线，未翻译=灰色点线 | 只选**文本块**；套索在此视图禁用 |

三种视图的“选择”互斥，避免区域框和块高亮打架：

- 文本块选择（点选、左键框选累加、右键框减）→ 仅原图 / 结果
- 区域选区（套索、矩形、浮动操作条）→ 仅原图 / 擦除后
- 区域操作（重检测/重擦除/恢复）结束后**只清区域**，文本块选择保留
- 切到擦除后：区域清空、块高亮隐藏（块选择值仍记住，切回原图/结果恢复）

- 擦除视图的红点来自「原图 → 擦除图」的亮度差（只标变亮的部分，即被抹掉的墨迹）
- 结果视图拖框改的是 `blocks[].bbox`，防抖后自动重排，所见即所得
- 三种视图缩放/平移一致，切换不跳动

- 编辑（拖框、改文本、改样式）始终在**原图坐标系**上进行，叠加框画在任何预览之上
- `运行本页` / `排版本页` 成功后自动切到「排版结果」
- 区域擦除成功后自动切到「擦除后」
- 没生成过的视图会提示并退回原图；切页时保留当前预览模式
- **切换预览不会丢选区**（原图/擦除/结果之间来回切，虚线框和浮动按钮都在）
- 运行本页、排版本页后重新载入同一页时选区也保留；只有切换页面才清空
- 打开「排版结果」时，如果 `project.json` 比结果图新，会提示「结果图可能过期」

## 局部重绘（原地填充）

菜单/浮动条里的「局部重绘」现在是**整块填充**，不再依赖 CTD 文字掩膜：

- 掩膜 = 选区多边形本身，选区内所有像素都会被重绘（CTD 没检出的字也会被去掉）
- 平坦背景（气泡内部）取周围中值色填充
- 复杂背景用 OpenCV content-aware（`INPAINT_TELEA`）重建
- 若存在 `data/models/lama.onnx`，优先用 **LaMa** 做纹理级重建，效果接近 PS 内容识别填充
  （首次调用要加载 208 MB 权重，约 20 秒；之后每次约 2 秒）

```
python -m mangatl fetch-models --lama      # 下载 LaMa 权重（约 208MB，可断点续传）
```

- 每次重绘都从**当前 `inpainted/` 继续**，多次局部重绘会叠加
- 区域操作结束后统一收尾：选区、浮动按钮、块高亮清空（添加块时保留新块选中）

手动添加的文本块固定为 `dialogue`，不会被角色分类器判成 `texture`，所以译文一定会出现在结果图里。

## 行为回归测试

`tests/test_gui_audit.py` 用真实窗口覆盖这些高风险组合（约 24 个场景 + 4 组随机操作）：

- 撤销：LIFO、切页保留、旋转/移动/样式、图片文件不被误删、撤销时取消待执行的自动重排
- 视图：原图/擦除/结果各自可用的交互，结果视图禁用套索，缺结果图时回退
- 选区：框选累加、右键减选、Esc 取消、切页清空
- 块操作：手动块固定对白、删除后重编号、表格编辑落盘
- 渲染：锁字号在改框后不变、`text_bbox` 不动检测框
- 健壮性：坏图片不清空画布、随机操作后 `project.json` 的 id 仍连续

```bat

```

## 运行 / 批量（子进程 + 监视）

原来的「运行」和「批量」已合并为一个 **运行** 面板，顶部的
「运行当前页」取代了旧的「运行全部页」按钮。任务都在**独立子进程**里跑
（`python -m mangatl run ... --events-json`），所以识别/排版再重也不会把编辑器卡死；
UI 只读它的事件流。

| 控件 | 作用 |
|---|---|
| 运行当前页 | 用子进程跑当前页（等价于旧的「运行本页」） |
| 开始批量 | 按下面范围/阶段跑（云端翻译缺 Key 时直接提示；本地引擎不需要 Key） |
| 页码范围 | 起止数字框始终可编辑，中间是「到」；勾「全部」用整本，手动改数字会自动取消「全部」 |
| 阶段 | 检测 / OCR / 翻译 / 擦除 / 排版 |
| 跳过已完成 | 默认开；子进程按阶段标记自动跳过，即断点续跑 |
| 强制重跑 | 传 `--force`，忽略阶段标记 |
| 卡住阈值 | 默认 60 秒，可改 |
| 开始 / 停止 | 停止 = 请求子进程退出，15 秒未退则强杀 |
| 重试失败页 | 只对这些页再跑一次（`--pages 3,7 --force`） |

### 怎么判断“在跑”还是“卡住”

面板底部有**心跳行**，每秒刷新：

```
心跳：3s 前 · 012.jpg · 阶段 擦除 · 已用 47s
```

| 距上次事件 | 状态 |
|---|---|
| < 阈值/3 | 正常（心跳行持续变化） |
| 阈值/3 ~ 阈值 | 变慢（仍在跑） |
| **≥ 阈值（默认 60s）** | 弹出提示条：`90 秒没有新进展，可能卡住`，按钮「终止进程 / 继续等待」 |

子进程每 3 秒还会主动发一条 `tick` 心跳（`--heartbeat 3`），所以即使某一页内部很久没有阶段事件，也能看到进程活着。

### 日志

- 子进程 stderr（模型加载、警告、traceback）逐行进入日志面板
- 事件摘要（页完成、跳过、失败）也写日志
- 「导出日志」保存为 txt，便于排查

### 已验证

- CLI 事件流：`page-start / stage-start / page-done / summary` 按 NDJSON 输出
- 事件解析与看门狗阈值：单元测试
- UI 逻辑：注入事件后表格/进度正确，90 秒静默时提示条出现，点「继续等待」后消失

## 三个独立的几何

| 视图 | 编辑的几何 | 存储字段 | 影响 |
|---|---|---|---|
| 原图 | 检测/OCR 框 | `bbox`（+ `bubble_bbox`） | 检测、擦除、气泡归属 |
| 擦除后 | 区域选区 | 不落盘（临时多边形） | 只影响本次擦除/恢复 |
| 结果 | **排版文字框** | `text_bbox`（为空时用 `bbox`） | 只影响文字位置 |

所以在结果视图拖动文字框**不会**改变原图上的检测框；切回原图，蓝色框仍在原位置。想消除两套框的差异，可以在结果视图里把框拖回原位，或把原文框也调成一样。

## 自由变换（结果视图）

选中块后，框上方多一个**蓝色圆点手柄**：

| 操作 | 效果 |
|---|---|
| 拖框内 | 平移 |
| 拖 8 个白色手柄 | 缩放（可非等比） |
| 拖蓝色圆点 | **旋转**，按住 `Shift` 以 15° 吸附 |
| 松手 | 写入 `blocks[].bbox` / `blocks[].rotation`，约 350ms 后自动重排 |

旋转的实现：文字先画到透明图层，再绕框中心旋转后合成到页面，所以旋转只影响文字，不会带着背景一起转。旋转后文字可能超出气泡，需要再平移/缩放框来收进去。

**样式锁定**：首次拖动/缩放/旋转某个框时，当前**字号、前景色、描边色、描边宽度**会写进该块的 `style`；框移动时不再从所在位置的像素重新估计颜色，所以文字不会一边拖一边变色。之后框怎么变，字号都不再重新适配（只会重新断行），因此拖框是"移动画框"而不是"拉伸文字"。同时 `bubble_bbox` 会跟随新框，文字不会再被旧气泡范围裁住。想让某块恢复自动适配，把字号改回 `0` 即可。

旋转角度会显示在右侧「编辑」面板的 meta 行（`旋转 55°`）。

## 自动预览（实时重排）

工具栏预览组里有一个勾选按钮「自动预览排版」，默认开启：

- 修改文本 / 样式 / 框位置 / 删除 / 撤销 后，**约 350ms 防抖**后自动重排当前页
- 若当前正在看「排版结果」，画面会就地刷新（保留缩放、平移和选区）
- 关掉后只在点「运行本页」「排版本页」时重排
- 排版失败（例如某块字体缺失）只在状态栏提示，不会打断编辑

- **拖动块内任意位置**：移动整个框（自动限制在页面内）

## 文本块操作

| 按钮 | 行为 |
|---|---|
| 应用并排版 | 写回原文/译文/角色/样式，重算角色并立即重绘 |
| 重新识别 | 对该块单独跑 manga-ocr，结果填入原文框 |

| 打开结果图 | 用系统看图器打开排版结果 |

## 与流水线的关系

编辑器**不会**自动跑整条流水线；它直接操作 `project.json` 和 `inpainted/`、`result/`：

- 想先自动处理，再手工修：先跑 `python -m mangatl run ...`，再开 GUI
- 修正后继续用 CLI 跑后续阶段也没问题，阶段完成位会一起更新

## 当前限制（MVP）

- 没有图层/蒙版编辑，套索只用于区域操作
- 撤销只覆盖块列表，不撤销文件写入（重跑流水线可重生成）
- 画布暂不支持旋转/翻转
- 字体依赖系统中文（Windows 自带微软雅黑即可）

在「设置」里选预设即可自动填端点/模型；本地模型把 ollama / LM Studio / llama.cpp
按对应端口跑起来，底部翻译引擎选同名项，批量任务就能离线翻译。

环境变量 `MANGATL_API_KEY`、`MANGATL_BASE_URL`、`MANGATL_MODEL` 优先级最高，
可覆盖界面设置。

## API Key 的保存方式

- 界面里勾「记住 Key」后，Key 用 **Windows DPAPI** 加密写入 `data/secrets.bin`
  （绑定当前 Windows 用户与机器，拷走文件也解不开）
- 端点/模型/预设是明文，写入 `data/settings.json`
- 启动时自动读取并注入 `MANGATL_*` 环境变量，子进程（批量任务）直接继承
- 日志、异常信息都不会包含 Key
- 不勾「记住 Key」则只存在当前进程内存里，关掉即失效
